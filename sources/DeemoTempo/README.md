# DEEMO Trainer 0.9 beta 2

适用于 DEEMO 5.0.8（1001405，com.rayark.pluto），适配的 UnityFramework UUID 为 37b8f14d-ccfd-3358-8c31-cbe88ff67b2a。升级沿用原软件包 com.linghe.deemotempo，Sileo 版本为 0.9~beta2。

在 Sileo 安装后，桌面会出现带银色扳手的 **DEEMO Trainer**。首次安装或升级后，从多任务界面完全退出 DEEMO 并重新打开一次，载入新版。桌面应用和游戏浮窗共用一份设置。随包安装的设置服务以 mobile 身份保存每一项变更，再通知两端原地刷新。切回前台时会读取最新值。升级会尝试沿用旧版已保存的配置。

桌面应用顶部的“启用练习器”默认开启。关闭时游戏内工具栏和面板消失，取消循环，退出插件暂停，恢复原速。正在拖动时回到拖动前的位置。游戏自己的暂停菜单仍由游戏控制。重新开启会应用当前保存的倍率；DEEMO 在后台挂起时，回到游戏后读取开关。为支持曲中随时重新开启和回放，已载入的适配器在关闭期间仍记录本局原生判定。已经使用过练习功能的当局继续按 0% 结算，之后全程关闭的新局正常计分。

在桌面或游戏内可调整配色、拖动灵敏度、声音延迟及歌曲倍率。速度范围 0.10× 到 2.00×，每档 0.05×，共 39 档，显示两位小数。升级后会在首次启动游戏时将旧倍率取至最近一档；桌面已设置的值优先。选曲时点左上角倍率按钮，开曲后按钮移到进度条左侧。倍率显示逐档同步，滑动停顿约 0.12 秒后更新歌曲音频，“恢复 1×”可回到原速。

## iPad 兼容性

桌面应用和游戏插件均按 arm64、最低 iPadOS 15.0 构建，以 Rootless 布局打包。插件按游戏构建号和 UnityFramework UUID 校验，没有 iPad mini 6 机型限制。普通 iPad、iPad Air、iPad mini 和 iPad Pro 只要能运行该游戏构建，且设备的芯片、系统和越狱支持 Rootless 插件加载，均可试用。同一市场版本若包含不同的游戏二进制，也需单独适配。其他机型及 iPadOS 15 的兼容性为构建和代码层面判断，尚无本版真机验收。越狱支持的具体系统与芯片组合请查阅 [Dopamine 官方说明](https://ellekit.space/dopamine/)。

歌曲顶部从左到右依次是倍率、进度条、暂停、区间和设置。工具栏高 56 pt，按钮及留白由独立窗口接住触摸。进度条上实心大点为播放头，淡色小点为手指目标。默认灵敏度下，播放头追赶速度约为 0.3.1 版的 40%，最高每秒 36 秒原曲时间。拖到曲首、曲尾或已选区间边界时，最后一步停在边界。按住期间音频暂停，谱面跟随白点滚动，松手从播放头位置继续。点击暂停键，播放和判定冻结，仍可拖动、设区间和调速。再点一次继续。

点击齿轮可选择白色、深色或浅蓝配色，并将进度条拖动灵敏度设为 25%–250%。100% 沿用 0.4.0 的速度，较低的数值适合精细定位。两项设置立即生效，下次启动沿用。调整外观或灵敏度本身不会触发练习结算。

区间键显示下一步。点“1”在当前播放头设红色起点，点“2”在其后设终点。如果播放头早于起点，点“2”会把起点移到当前位置。在同一时刻重复点击会保留起点。区间成立后两个标记变绿，轨道线后方显示淡绿色选区，播放到“2”即回到“1”，拖动也限在两点之间。点“×”取消。可先暂停、拖动选准两个位置，再继续播放。

向后拖会按实际判定时刻撤销后续记录，恢复此前的分数、当前与最高连击、Perfect 和 Miss。提前命中的音符按实际命中时刻处理。向前拖会将途中尚未判定且已越过的可打音符各记一次 Miss，同时处理和弦，背景音符不计 Miss。反向拖动再向前时，从本次拖动到达的最早时间重新计算。若实际判定数量和已记录事件不一致，插件停止接受跳转，保留原局状态。

如果设备上的音画有稳定偏差，先用游戏原有的 1× 校准，再在倍率菜单打开“延迟微调”。正值使谱面向后对齐，单位为毫秒，范围 −200 到 +200，默认 0。音频效果无法建立时本曲回到 1×，曲后倍率菜单显示原因。

## 工作方式

正式 BGM 的 Unity AudioSource 按所选倍率读取歌曲，在其自己的 FMOD 通道组增加反向音高修正。0.5× 及以上使用 512 帧分析窗口，更低倍率使用 4096 帧窗口和最多四级音高修正，并按级数估算延迟。源音高乘倍率、各级效果器的音高乘数之积等于倍率的倒数。不同倍率和瞬态密集的钢琴段落可能产生不同的音色和延迟。保留原引擎的解码、混音、音量及重试流程。

游戏的主协程按帧推进谱面，并用 BGM 样本位置校正。适配器为此协程换算帧时长、延迟起播、恢复定位和送入校正的样本数。按键音保留原采样音高和力度，仅换算发声等待和时值。暂停期间冻结按键音的等待时钟。整组音符和原有判定逻辑继续使用游戏的歌曲时间，判定窗口以歌曲时间计。开曲时选择非 1× 倍率、在曲中改变倍率、使用插件暂停、开始拖动或放下第一个区间标记，都会将本局标为练习。恢复原速或取消区间仍保留标记。单独打开倍率面板查看不会触发。练习中照常判定，结算时用本局总音符数生成全 Miss 的原生结果，完成度为 0%，最高连击和命中数为零，AC 和 FC 均关闭。游戏原生重试会开始新的一局。

插件也监听对本曲 BGM 作出的额外定位、暂停和调音，并比较 Unity 的两个帧时钟，持续约半秒的游戏时间缩放也会标记本局。其他插件如果直接改变系统时钟或使用不同音源，可能无法识别。

src/Tempo.hpp 包含倍率换算和可替换的音频后端接口。src/Deemo508.hpp 与 src/Adapter.mm 是该版本的适配。更换游戏时要重新识别 BGM、歌曲时钟、按键音和生命周期。包内不含游戏的代码、曲目或谱面。

## 验证与构建

在 Linux/WSL 设置 DEEMO_TOOLROOT 指向本地 ShadeBar 交叉编译工具目录，运行 bash build.sh。构建会运行时钟/回退测试，并生成已签名的 arm64 桌面应用及游戏动态库。在本软件源目录布局下运行 python package.py，再运行仓库的 tools/update_repo.py 及其 --check。安装包为 com.linghe.deemotempo，包架构为 iphoneos-arm64。

可在持有原 IPA 的机器运行 python tests/verify_ipa.py <IPA> 校验应用版本、UUID、62 个入口与 37 处关键调用，并核对结算对象从游玩场景传至结算页的读写位置。python tests/chart_check.py <IPA> [UnityPy依赖目录] 读取原谱面。python tests/render_tone.py [fmod_toolkit依赖目录] 用桌面 FMOD 渲染测试音。桌面 FMOD 和此游戏内的 FMOD 版本不同。

本次检查覆盖 0.100–2.000 范围内 1,901 个倍率的五分钟时钟换算、效果创建失败回退和释放、三首歌共九张谱面及 8,883 个按键音事件。桌面 440 Hz 长音在十二个抽测倍率下的稳定音高为 439.98–440.02 Hz，含 0.10× 与 2.00×。极低倍率会增加处理延迟，钢琴起音的清晰度和真机性能需要试听。尚未在 iPad 上实际安装、录音或测量触击判定。设备验收可从 0.75× 开始，比较曲首与曲尾，暂停恢复后再对拍，随后重试并测试 1.25× 和 1×。如果出现持续漂移，请记录歌曲、难度、倍率、输出设备和发生时刻。

进度功能验证覆盖距离追随、往返与取消、边界和弦、提前命中、晚判 Miss 及去重。尚无本版在 iPad 上实测的画面或成绩记录。建议先在短曲比较前跳的 Miss 数、回到同一时间后分数/连击，以及倍率改变后的重打与续播。

0.3.1 的 tests/native_preview.py 在 ARM64 模拟器中执行此 IPA 的原版位置协程，以渲染接口替身记录坐标和透明度。六次来回定位均得到符合谱面时间的可见坐标。此检查未覆盖 iPad 的实际画面呈现或帧率。

0.4.0 的区间测试覆盖重设起点、重复点击同一点、区间内外拖动及八次循环回溯。tests/native_score.py 使用原版计分函数和 818 个可打音符，检查全命中时的分数与 AC/FC，再检查练习结算的零分、818 个 Miss 和两个标志。真机验收可在暂停时设起止点并来回拖动，恢复播放后观察循环，在取消区间与恢复 1× 后完成歌曲，核对结算，再用 1× 原样完成新一局作对照。

0.4.1 在回跳和开始拖动时清理上一段音符的视觉特效，恢复连击数时避免重新播放 Charming。tests/native_effects.py 在原版 ARM64 代码上连续八次运行对象池清理和 Charming 收尾，检查特效被隐藏、颜色的透明度归零，并覆盖暂停状态。
